# Contributing

## Before your first change

```bash
npm ci
npm run doctor
```

`npm run doctor` tells you whether this machine can run the whole workflow and
names the fix for anything missing. Start there if a command misbehaves.

## The shape of a change

A film is three tracked files: `work/<brand>/<slug>/film.json`, `beats.html`
and `NOTES.md`. Everything else in that directory is generated by
`npm run pre`, gitignored, and never edited by hand. If you find yourself
editing a generated file, you are editing the wrong file.

Read [AGENTS.md](AGENTS.md) before you start. It is the full contract, and it
applies to people as well as to coding agents.

## Before you open a pull request

```bash
npm run ship <brand> <slug>
```

That runs everything: prepare, the repo guard, the formatting law, upstream
lint, gate 1 in a real browser, the build, and gate 2 on the shipped bytes. It
stops at the first failure. Every gate must be green.

Then open the film and watch it:

```bash
npx hyperframes preview work/<brand>/<slug> --background
```

A gate sees that a film is broken. It cannot see that a film is wrong. Look at
the first frame, every beat boundary, and any beat sitting on a different
surface from the one behind it.

## What a reviewer will check

- The diff touches only what it needs to. A film change does not edit `lib/` or
  `tools/`.
- Nothing generated is committed. `git status --short` is clean after
  `npm run pre`.
- No em dash anywhere in tracked text. Use a comma, a colon or a full stop.
- Comments say why, not what. No walls.
- No new dependency, abstraction or test unless it protects behaviour that
  would otherwise break silently.
- No check was loosened to make a failure go away. If a limit genuinely has to
  move, move it where it is reviewable: a film's own `budget` in `film.json`,
  not a threshold in a tool.

`npm run guard` enforces most of that, and it runs inside `npm run lint`. CI
runs the same commands on Linux, macOS and Windows.

## Reporting something broken

Open an issue with the film, the command you ran and the output. A gate
failure message names the file and the line in `beats.html` you would edit, so
paste it whole rather than summarising it.
